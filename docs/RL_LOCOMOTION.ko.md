# 강화학습 보행 — 환경, 보상, 단계 (2026-09-29 시작)

사용자 목표: 걷기, 빠른 달리기, 점프, 울퉁불퉁한 지형, 높은 곳에서 뛰어내리기, 가파른 경사.
이 문서는 **학습 환경과 계획, 실제 측정 결과만** 기록합니다. 보상이 높다는 것만으로 성공이라고 쓰지 않습니다.

## 고정 조건

- 능동축 10개(`--dof 10`, `sim/raptor_digitigrade.xml`) 또는 발목 roll을 더한 12개
  (`--dof 12`, `sim/raptor_digitigrade_ankleroll.xml`). 둘 다 URDF 변환, 17.3kg.
- 정책은 50Hz로 **능동 관절(10 또는 12개)의 위치 목표만** 출력합니다. Gazebo와 같은 위치 서보 경로
  (10ms마다 위치 읽기, 이득 30/s, URDF 속도·토크 한계)를 거칩니다. 언어 모델은 이 행동을 만들지 않고,
  STOP은 정책 밖의 위치 유지입니다.
- 관측은 실제 로봇에 있는 값만 씁니다: IMU 각속도·중력 방향, 관절 위치·속도, 직전 행동, 속도 명령, 걸음 시계.
- 물리: MuJoCo 1ms, 접촉 설정 변경 없음. 지형은 평면, 상자(경사·계단·단상), height field(요철)입니다.
  레이캐스트로 잰 표면 높이가 보상 계산용 높이 격자와 일치합니다(`tests/test_rl_env.py`).

## 보상 (초당 가중치, `sim/rl/raptor_env.py`)

| 항목 | 가중치 | 의미 |
|---|---:|---|
| 속도 추종 (x, y) | +2 | exp(−오차²/0.1) |
| 회전 추종 (yaw) | +1 | exp(−오차²/0.2) |
| 생존 | +0.5 | 넘어지지 않은 시간 |
| 발 공중 시간 | +1 | 착지 시 (공중 시간 − 0.25s), 0.5s 상한. 이동 명령일 때만 |
| 수직 속도 · 좌우/앞뒤 회전 속도 | −2 · −0.05 | 몸통 출렁임 |
| 자세 | −5 | 중력 방향의 수평 성분² |
| 몸통 높이 | −20 | 기준보다 내려앉은 양² |
| 토크 · 관절 가속 · 행동 변화 | −2e−5 · −2.5e−7 · −0.02 | 에너지와 떨림 |
| 발 미끄럼 · 관절 한계 근접 | −0.2 · −5 | 디딘 발의 수평 속도², 범위 90% 초과분 |
| 몸통·꼬리 지면 접촉 | −5, 종료 | 넘어짐으로 처리 |
| 넘어짐 | −10, 종료 | 기울기 0.8rad 초과, 몸통 높이 0.5m 미만 |

무작위화: 지면 마찰 0.5~1.25, 몸통 질량 −1~+1.5kg, 토크 한계 ±10%, 에피소드당 한 번 밀기(±0.4m/s), 초기 관절 잡음.
커리큘럼: 최근 넘어짐 비율이 20% 미만이면 지형 난이도 +0.1, 명령 속도 ×1.15. 50%를 넘으면 난이도를 내립니다.

## 단계

1. **평지 보행**: 명령 0.2 → 0.6m/s, URDF 구동기 그대로.
2. **지형 커리큘럼**: 요철(±5cm), 경사(3→25°), 계단(2→12cm), 단상 내려가기(5→40cm).
3. **구동기 사양 검토**: 달리기와 점프는 관절 속도 한계(2~3rad/s)의 물리 상한을 먼저 측정합니다
   ([증거 75](evidence/75-feasibility/README.md)). 사양을 바꾼 결과는 **다른 가상 구동기의 결과**로 분리해 보고합니다.
4. **점프·달리기 기술**: 3단계 결과와 사용자 결정에 따라 진행합니다.
5. Gazebo 재검증: 같은 관측·행동 계약으로 ROS 정책 어댑터를 만들고 STOP 우선순위를 유지합니다.

## 실행

```bash
.venv-sim/bin/python sim/rl/train.py --name walk_flat_v1 --terrain flat --steps 15e6
.venv-sim/bin/python sim/rl/evaluate.py sim/rl/runs/walk_flat_v1/model.zip --commands 0 0.2 0.4 --video walk.mp4
```

M5(10코어) CPU에서 환경 8개로 초당 약 1,900 제어 스텝을 얻었습니다(측정). 학습 산출물(`sim/rl/runs/`)은 Git에 넣지 않습니다.

## 결과

| 학습 | 결과 | 기록 |
|---|---|---|
| 10축 평지 v1~v3 | 무효. 넘어지지는 않지만 명령을 따르지 않음(속도 보상 결함: 자유 관절 원점 속도 사용) | [78](evidence/78-rl-baseline/README.md) |
| 12축 평지 (kv 30, roll armature, 10축 정책 이식) 1,500만 스텝 | 0~0.6m/s 명령 추종, 넘어짐 0/16, 명령보다 약 0.1m/s 느림. 지형은 zero-shot 실패 | [79](evidence/79-rl-walk12/README.md) |
| 12축 단계 A~B3 (서보 경로 → 무작위화 묶음별) | 결정적 평가로 잡음·지연 견고성 향상. 학습 로그 넘어짐 급증은 확률적 행동 때문. 힘 펄스 40N이 주원인(한계 20~30N) | [82](evidence/82-dr-ablation/README.md) |

학습 중 발견해 고친 결함: 서보 kv 100의 발 떨림(→ kv 30), 속도 측정 기준점, 발 미끄럼 속도,
12축 발허리뼈 접촉을 몸통 충돌로 판정, 발목 roll 서보 ±90rad/s 떨림(→ 회전자 관성 0.01).

## T1 달리기 환경 (2026-09-30, `sim/rl/run_env.py`)

**첫 행 규칙:** 이 환경의 모든 결과는 **T1 가상 구동기** 결과입니다 — R-02 형상, 질량 균일 축소 5 kg(발가락 스프링 고정),
스프링 (c)(엉덩이 130 N·m/rad 단방향, 무릎 40 양방향, 발목 57 단방향), 구동기 엉덩이 35 N·m/27 rad/s/350 W,
무릎 28/27/225, 발목 22/27/90(정지 기립 예압 때문에 §9의 8에서 상향, [사양서 §9](design/40kmh-spec.md)), 꼬리 36/12/400,
1 ms마다 토크·속도·전력 클램프, 몸통 속도 관측(상태 추정기 가정). 현재 로봇의 구동기가 아닙니다.

- 행동: 12축 위치 목표(꼬리 피치·요 포함, `--tail locked`면 10축), 50 Hz. 기본 자세 엉덩이 −0.375 / 무릎 1.50 / 발목 −1.652.
- 보상(초당): 속도 추종 exp(−오차²/σ²) +3(σ = max(0.3, 0.15·v)), 진행 +1, 비행(두 발 공중, 명령 ≥ 3 m/s) +1, 유각 0.12~0.35 s +1,
  GRF 4 BW 초과 −1, 이동 비용(양의 기계 일률/(W·v)) −0.05, 무게중심 기준 각운동량(y·z) −0.5, 자세 −5, 높이(0.1 m 여유) −20,
  수직 속도 −0.5, 토크 −1e−5, 행동 변화 −0.02, 관절 가속 −2e−8, 미끄럼 −0.2, 관절 한계 −5, 생존 +0.5, 넘어짐 −10·종료.
- 교란 커리큘럼(`level` 0~1, 넘어짐 비율 < 20 %면 +0.1, 명령 속도 ×1.15): 피치 임펄스 0.15~0.4 N·m·s(0.3/s), 요 임펄스(0.3/s),
  유각 발 걸림 0.5~1.5 W·0.06 s(0.5/s), 착지 시 피치 임펄스 0~0.3 N·m·s(착지의 30 %), 옆 밀기 ±0.4(1+level) m/s 1회.
- 로그: 몸 전체·꼬리·다리의 무게중심 기준 각운동량, 발별 GRF 최대값, 비행 여부, 양의 기계 일률.
- 평가(`evaluate_run.py`): 명령별 넘어짐·속도·보폭 주파수·듀티·비행 비율·GRF·이동 비용·꼬리 사용, 같은 정책의 꼬리 활성/고정 비교,
  요(또는 피치) 임펄스 회복 시간.

```bash
.venv-sim/bin/python sim/rl/train_run.py --name run_t1_v1 --steps 20e6
.venv-sim/bin/python sim/rl/evaluate_run.py sim/rl/runs/run_t1_v1/model.zip --commands 0 2 5 8 11.1 --tail both --impulses 0.3 0.6 1.0
```

측정: 환경 8개로 약 2,000 제어 스텝/s(1 ms 물리 20회 + 클램프).
