## 핵심 판단

지금 가장 가치 있는 내용은 모터 작동 영역, 실제 접촉과 센서, 몸에 맞춘 행동 데이터, 실패 기록과 재검증이다. 채널에서 유용한 아이디어를 많이 얻을 수 있지만 VLA나 시뮬레이터를 바꾸는 것만으로 랩터의 고속 보행·회복·정지 문제가 해결되지는 않는다. KAIST 로봇의 몸 편과 관련 HOUND 논문이 구조 비교에 가장 직접적으로 연결된다. [로봇의 몸 18:34](https://www.youtube.com/watch?v=oRgjzztNcWY&t=1114s) · [HOUND 논문](https://arxiv.org/abs/2312.17507)

네 구조 후보의 동일 조건 평가는 이후 완료했고, 후방 골반 8축을 보존한 상태에서 회전·속도·열·기립·정지의 통합 후보를 검증 중이다. 현재 후보들은 전체 기준에 미달해 구조나 실물 성능을 확정하지 않았다. 초기 평가와 반올림 오류 교정은 [증거87](</Users/danny/개발 모음 폴더/raptor/docs/evidence/87-structure-comparison/README.md>), 후속 실패와 재개점은 프로젝트의 WORK_STATE·PAUSE_CHECKPOINT 및 evidence 117–130에 보존했다. 최신 개발 비교는 기존 Adam 이력과 KL 제한을 유지한 학습률 변경이며 결과 미확정이다.

ASPIRE는 개발 과정에 지금 적용할 수 있다. 실패를 계층별로 기록하고 최소 수정 후 다시 실행해 확인하는 방법을 가져온다. 반면 로봇이 실물에서 자신의 제어 코드를 자동 변경하는 기능은 이번 제안에 포함하지 않는다. ER2와 RoboDawn은 검증된 동작을 선택하고 실행 결과를 다시 읽는 상위 계층 후보다. T-Rex는 접촉 반응과 느린 시각 판단을 분리하는 설계 원리로 참고한다. [ASPIRE](https://research.nvidia.com/labs/gear/aspire/) · [ER2](https://deepmind.google/models/gemini-robotics/embodied-reasoning/) · [RoboDawn](https://robodawn.top/) · [T-Rex](https://arxiv.org/abs/2606.17055)

## 조사 범위와 증거 수준

A는 현재 문제에 직접 연결되는 자료, B는 후속 기능 또는 비교 연구, C는 배경 자료, D는 현재 범위 밖이다. 우선순위는 분석자의 판단이며 영상의 품질 순위가 아니다. 일반 영상은 설명·공개 메타데이터를 수집했고, 관련 43편은 한국어 자동 자막의 핵심 구간을 대조했다. 추가 8편의 자막 요청은 HTTP 429 제한으로 실패하여 설명·메타데이터 수준으로 표시했고 재시도하지 않았다. Shorts는 제목·목록 선별 수준이며 독립적인 기술 검증 근거로 사용하지 않았다. 라이브 탭은 제공되지 않았다. 유료 강의·도서 전체·비공개 영상은 조사 범위에 포함하지 않았다.

YouTube 게시일과 블로그 재게시일이 다를 수 있다. 예를 들어 Agentic Robotics의 YouTube 게시일은 2025-08-02이며 검색된 블로그 날짜는 2026-02-19다. 아래 목록은 YouTube 메타데이터 게시일을 사용한다. 설명에 후속 강의 링크가 추가되어 있어 설명 내용의 갱신일을 최초 게시일과 같다고 볼 수도 없다.

## 1 기구와 모터부터 랩터의 실제 실행 범위를 정한다

KAIST 로봇의 몸 편은 단순한 연구 홍보보다 구체적이다. 18:34 이후에는 HOUND의 고관절·무릎 구동 관계와 관절 좌표에서 모터 좌표로의 변환을 설명한다. 연결된 관절에서 관절 각속도·토크를 각 모터의 사각형 한계와 따로 비교하면 실행 불가능한 상태가 남을 수 있다. [영상](https://www.youtube.com/watch?v=oRgjzztNcWY&t=1114s) · [원 논문 II-B~II-C](https://arxiv.org/html/2312.17507v1)

랩터는 이미 순간 4절 링크 전달비와 스프링 토크를 모델링한다. 따라서 다음 제안은 새로운 MOR 개념을 처음 넣자는 것이 아니라, 현재 모델의 전달비·효율·가속 및 제동·연속 토크 가정을 실제 부품에 맞게 확인하자는 것이다. 부품명을 붙였다고 그 곡선이 실측이 되는 것은 아니다. 좌우 평균 외에도 가장 많이 쓰이는 한 모터의 부하·포화·열 여유를 따로 봐야 한다. src와 run_env.py의 역할 및 사양서의 모든 축 예산을 같은 기준으로 맞춘다. HOUND의 기어 설계 연구는 기어비와 기어 치수·열을 함께 최적화하는 참고다. [HOUND 설계 연구](https://junny-kim.github.io/publications/projects/2022/HOUND/)

실행 제안은 한 주기의 모터 토크–속도 궤적을 시간 색으로 표시하고, 클러치·걸쇠 상태를 함께 기록하는 것이다. 가속과 제동을 구분하고, 전원 전압 저하와 역전류를 받을 수 있는지를 T2 부품 시험 항목으로 둔다. 8축 채택이나 새 기어비는 이 그림의 결과로 결정해야 한다. HOUND 사족의 최고 기록을 랩터 목표 속도로 가져오거나, 한 논문으로 모든 상용 모터가 불가능하다고 판단하지 않는다.

첨부 스프링 그림은 기능 위치 주석이다. 고관절 (c) 스프링·8축 무릎 걸쇠·독립 발목 클러치를 한 확정 제작품에 모두 달았다는 도면이 아니다. 공부노트 51~52쪽·60쪽을 대조했다. 추가할 제작 정보는 하중 경로, 고정점, 변형 범위, 연결·해제 조건, 핀·베어링 힘, 질량·관성이다. 이는 영상 확인으로 대신할 수 없는 랩터 고유 설계 항목이다.

## 2 보행과 접촉을 시각 판단보다 빠르게 닫는다

힘·촉각 편은 접촉의 존재, 힘의 크기, 미끄러짐을 구분한다. T-Rex는 느린 시각 행동 계획과 더 빠른 촉각 보정을 분리한다. 원 연구는 손 조작이며 랩터 발 보행의 직접 증거는 아니다. [힘·촉각 03:43](https://www.youtube.com/watch?v=T_Ptpq2_JiY&t=223s) · [T-Rex 01:51](https://www.youtube.com/watch?v=DDTqTzDUeQ8&t=111s) · [T-Rex 공식 구조](https://tactile-reactive-dexterous.github.io/)

랩터 적용 제안은 카메라 모델보다 먼저 발 접촉·하중·발 위치·몸통 자세에 대한 관측 계약을 만드는 것이다. IMU·관절 엔코더·모터 전류와 발 접촉 센서가 각자 무엇을 관측하고 무엇을 추정하는지 명시한다. 모터 전류를 발의 지면반력으로 곧장 바꾸지 않으며, 발 센서의 측정 대역과 센서 위치·좌표계를 기록한다. 센서마다 시각을 맞추고 지연·누락 상태를 로그에 남긴다.

제어 분리는 현재 코드의 20 ms 정책과 1 ms 물리·서보 계산에 이미 일부 나타난다. 이 시뮬레이션 설정이 실물에서도 보장되는 주기라는 뜻은 아니다. 시각 추론이 늦거나 통신이 끊길 때도 하위 제어가 유지될 필요가 있다. T-Rex 영상의 약 5/20 Hz를 랩터의 목표 제어 주기로 복사하지 않는다. 주기는 실제 접촉·착지·모터 응답 시험에서 결정한다.

랩터에는 정지 동작의 별도 검증이 필요하다. 공부노트 116쪽은 위치 유지 STOP이 고속 안전 정지를 보장하지 않는다고 명시한다. 정차 지원 스토퍼·브레이크·보조 접지점은 검토 가능한 기구 후보이며 기존 모델의 실패를 모든 수동 기립 구조의 불가능으로 일반화하지 않는다. 가장 작은 비교는 모터를 늘리는 것이 아니라 같은 구조에서 정차 하중 경로와 기립 자세를 시험하는 것이다.

## 3 시뮬레이션은 물리 시험과 시각 시험의 목적을 분명히 한다

Isaac Sim 활용 편은 환경·관측·행동·보상과 도구 선택을 설명한다. 디지털 트윈 편은 GRS·Gen2Sim·RoboTwin·Splatting Physical Scenes·SyncTwin·TwinRL-VLA 및 정책 평가를 다룬다. 특히 23:12 이후의 시각 표현과 물리 메시 분리는 현재 외형과 충돌체의 불일치를 이해하는 데 도움이 된다. [Isaac Sim 08:08](https://www.youtube.com/watch?v=6yeoSwPz2MI&t=488s) · [디지털 트윈 23:12](https://www.youtube.com/watch?v=g7y7y7xGpxU&t=1392s)

제안은 기존 MuJoCo 모델을 유지하고 외형·충돌체·관성·관절·스프링 계약을 따로 확인하는 것이다. 골반 위치를 옮길 때 탑재물과 꼬리 루트를 무엇에 고정하는지 명시하고 모델별 질량·관성을 재생성한다. 실사형 렌더링은 카메라 학습에 쓸 수 있지만 힘·마찰·관성 검증은 별도다. 자동 생성 보상도 제안으로만 사용하고 기존 실패 판정을 약화하지 않는다.

현재 공식 Isaac Sim 요구 조건은 x86_64 Ubuntu/Windows와 RTX GPU를 포함하고, aarch64는 DGX Spark 지원을 명시한다. Mac Docker 안의 ARM64 Linux만으로 그 조건이 충족되는 것은 아니다. 따라서 지금 이 조사를 이유로 Isaac Sim 설치나 장비 구매를 진행하지 않았다. 후속 비교를 하더라도 단일 모델의 기립·접촉·기본 서보 시험으로 엔진 차이를 먼저 측정한다. [Isaac Sim 공식 요구 조건](https://docs.isaacsim.omniverse.nvidia.com/latest/installation/requirements.html)

월드 모델 영상들은 조건부 미래와 행동을 연결하는 연구를 소개한다. 랩터 적용은 시각 데이터 다양화나 장면 후보 비교부터 시작하는 편이 타당하다. 생성 영상의 무전도 모습은 실물 안정성이나 모터 열의 증거가 아니다. 기존 MuJoCo 로그에서 계산한 물리 지표와 동일한 완료 조건을 만족하는지 따로 확인해야 한다.

## 4 타조 시연과 실패 기록을 실행 가능한 데이터로 바꾼다

DexCap·AirExo, 물리량 시연, π*0.6와 π0.7, Grounding Bottleneck 영상들은 각기 다른 방식으로 행동 데이터의 의미와 품질을 다룬다. 원 연구의 손·팔 시연을 랩터 관절각 정답으로 쓸 수는 없다. 데이터 변환 연구 의제는 데이터·몸·세계·보상 인터페이스를 구분한다. [행동 데이터](https://www.youtube.com/watch?v=DycoYh6imj8) · [물리량 시연](https://www.youtube.com/watch?v=RTyCQPtLN98) · [원 관점 논문](https://arxiv.org/abs/2606.06556)

랩터 적용 제안은 현재 rollout에 설계 변형·모델·정규화 해시, 목표 속도, 실제 속도, 접촉 위상, 착지 발 속도, 모터 포화, 스프링 연결 상태, 열 지표, 전도 원인을 붙이는 것이다. 서로 다른 정책의 최고 속도와 회전 성능을 한 로봇의 통합 능력처럼 합치지 않는다. 실패 데이터를 모두 버리지도, 좋은 행동처럼 그대로 모방하지도 않는다. 보상과 품질 라벨의 의미를 먼저 정한다.

RECAP은 시연·자율 경험·사람 교정과 보상을 활용하는 VLA 학습 연구다. 현재 PPO의 간단한 옵션이 아니다. π0.7 공식 자료는 낮은 품질 데이터도 메타데이터로 구분해 활용한다고 설명한다. 이 조사의 제안은 그 아이디어에서 데이터 스키마를 가져오는 것이며 랩터에 같은 모델을 이식하자는 결론이 아니다. [RECAP 원 논문](https://www.pi.website/download/pistar06.pdf) · [π0.7 공식 글](https://www.pi.website/blog/pi07)

추가 조사에서 찾은 APT-RL은 단순 동역학·궤적 최적화로 동작과 제어 데이터를 만들고 스킬을 사전 학습한 후 지형에 적응시키는 접근이다. 랩터에서 직진과 회전의 교환 관계를 풀고자 할 때 참고할 후속 후보다. 원 연구는 사족이며 원시 토크 출력 등 현재 랩터 구조와 차이가 있다. 기구 동결 전에 통째로 전환하지 않는다. [APT-RL](https://arxiv.org/abs/2607.13579)

## 5 AI는 실행 가능한 행동과 상태 전이를 통해 연결한다

Agentic Robotics, ER2, RoboDawn은 상위 판단을 하위 실행에 연결하는 데 유용하다. RoboDawn은 이동·회전·그리퍼 같은 작은 명령을 계획·IK·제어 계층에 넘기고 실제 실행 결과를 다시 관찰한다. ER2 공식 모델 카드도 VLM 및 텍스트 출력을 명시한다. 두 접근을 고속 관절 토크 생성기로 해석하면 역할이 달라진다. [Agentic Robotics](https://www.youtube.com/watch?v=1yl5TQuKNcU&t=249s) · [RoboDawn](https://arxiv.org/abs/2609.22966) · [ER2 모델 카드](https://deepmind.google/models/model-cards/gemini-robotics-er-2/)

랩터의 상위 API는 목표와 시간 제한·좌표계·실행 전제·완료 조건을 가져야 한다. 현재 구현된 STAND/PAUSE/RESUME/STOP과 아직 거부하는 탐색·이동을 구분한다. 상위 모델에는 현재 사용 가능한 행동만 노출하고, accepted·started·completed·failed를 다른 상태로 보고한다. 완료 판정은 모델의 문장보다 실제 센서·제어 실행 상태를 우선하도록 설계한다. 기존 request ID·중복 처리·추종 확인 기능은 보존한다.

Laya와 VLM의 연결은 공부노트의 후속 단계다. 명령 선택 후보의 비교는 위험 문장 오수락, STOP/PAUSE/RESUME 혼동, 방향 혼동, 오래된 관측, 통신 누락을 포함한 새 독립 세트로 한다. ER2나 새 VLM이 좋아 보인다는 인상만으로 교체하지 않는다. 언어 모델의 판단 지연과 로컬 보행 루프를 분리한 상태에서 연결 전체를 측정한다.

## 8 실행 순서와 측정할 결과

## 한계와 추가 검증
