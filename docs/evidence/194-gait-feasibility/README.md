# 194 달리기 가능성 비RL 검사(F2): 직접 짠 제어기로는 2 m/s도 유지하지 못함 — 미해결 (탐색 실패, 기구 판정 아님)

2026-11-03. [형상 동결 계획](../../DESIGN_FREEZE_PLAN.ko.md)의 F2 단계다. 지금 형상(R-03)에만 시도했다. MuJoCo + RobStride 모터 한계 조건이며 실물이 아니다.

## 결론

- **직접 짠 달리기 제어기 2종을 교차 엔트로피 방법(CEM)으로 맞췄지만 안정된 달리기를 찾지 못했다.** 계획의 중단 규칙(2구간 개선 없음)으로 멈췄다. 약 1시간 사용, 형상당 예산 2시간.

| 제어기 | 속도 | 탐색 중 가장 오래 버팀 | 실물 조건 재생(`RunEnv.step`) |
|---|---|---|---|
| 시계 보행(보폭 빈도·디딤 비율 고정) | 4 m/s | 2.6 s / 3 s | 1.0 s 버팀, 평균 3.9 m/s |
| 접촉 전환 Raibert식(발 디딤 = 속도 피드백) | 2 m/s | 3.0 s / 3 s (한 후보) | 0.44 s 버팀 |
| 같음, 출발 3 m/s | 4 m/s | 2.8 s / 3 s | 0.44 s 버팀 |

- **실패 양상:** 지지 시간이 0.07초로 제어 주기(0.02초) 3–4번뿐이다. 두 발이 같이 닿아 튀고, 몸통 속도가 −3.8에서 +7.6 m/s까지 흔들린다. 그러다 옆으로 기울며 넘어진다. 50 Hz 위치 명령으로는 손으로 짠 구조가 접지 충격을 다루지 못했다.
- **이 결과는 기구 판정이 아니다.** 같은 다리 형상(R-02 구간 0.22 : 0.38 : 0.32 m)에서 학습 정책은 50 Hz로 5.6–6.1 m/s를 달렸다(증거 169·174, 11.3 kg rev2 모델). 실패한 것은 제어기 구조이고, 형상은 아니다.
- **그래서 F2의 목적(형상별 달리기 비교)은 이 방법으로 이루지 못했다.** 형상 결정은 F1 계산(증거 193)과 기존 학습 기록으로 해야 한다. 동역학 확인은 형상을 정한 뒤 짧은 학습 probe로 대신해야 한다.

## 방법 (`gait_cem.py`)

- 제어기는 매 제어 주기(0.02초)에 관절 목표를 낸다. 정책과 같은 방식이다.
  - 시계 보행: 지지 중 고관절이 착지각에서 이륙각으로 움직이고 몸통 pitch PD를 더한다. 유각 중 무릎을 접고, 착지각은 속도 오차로 옮긴다.
  - 접촉 전환: 발 하중으로 착지를 감지하고, 지지 시간이 다 되면 이륙한다. 착지 고관절각은 중립점 v·Ts/2에 속도 피드백을 더해 정한다.
  - 공통: 고관절 roll은 몸통 roll·옆 속도 피드백, 꼬리 pitch는 몸통 pitch PD, 꼬리 yaw는 회전 속도 감쇠다.
- 탐색: 매개변수 14개, 개체 64–96개, 30–40세대.
  - 출발: 서 있는 자세에서 몸통 속도 min(v, 2–3) m/s, 명령 속도를 2–3 m/s²로 올린 뒤 3초 유지.
  - 점수: 버틴 시간 + 속도 추종.
  - 탐색 중에는 모터 한계(`RunEnv._clamp`)만 걸고 물리를 직접 돌렸다.
- 재생: `RunEnv.step`으로 지연·센서 잡음·발열·목표 램프를 모두 켰다.

원자료는 `eval/` 폴더의 `clock_current.log`, `event_current*.log`, `gait_current*.json`이다.
