# 105 — loaded 관측 48차원 후보 초기화

증거104의 합성 반사실에서는 관측에 없는 loaded 상태가 스프링 연결과 다음 움직임에 영향을 주었다. 이번에는 기존 46개 특징 뒤에 직전 제어 단계의 loaded[left]/loaded[right] 두 값을 선택적으로 붙인다. 실제 클러치 센서나 모든 숨은 상태를 추가한 것은 아니다. 스프링 정지길이·수동 발가락·열 상태 등은 여전히 직접 입력하지 않는다.

기본 obs_contact=False는 기존 관측과 물리를 유지한다. 후보도 행동 8개이며 목표 배율·기구·모터·질량·보상·명령 카탈로그를 바꾸지 않는다. args.json과 env_kwargs를 통해 평가 환경도 복원한다. 반사 시 loaded의 좌우를 교환하고, 위상은 기존 위치에서 부호를 반전한다.

배우·가치망의 첫 입력 가중치에 0인 두 열을 붙였다. Adam의 기존 모멘트 열을 보존하고 새 열은 0으로 확장했다. 원 배우의 고정 평균·표준편차를 사용하고 추가 특징은 평균0·표준편차1이다. 외부 VecNormalize는 관측 정규화를 하지 않으며 source의 reward 통계를 보존한다. 이번 새 대조·후보는 학습 시작 시 torch RNG를 모두 seed0으로 설정한다. 이전 대조 학습과 같은 잡음 순서라고 주장하지 않는다.

실제 source인 seq_compare_catalogue에서 초기 대조·후보를 저장하고 복원했다. seed47001의 yaw−1/0/+1, 각각10초·500제어주기, 총9rollout에서 source·대조46·후보48의 행동·qpos·qvel이 정확히 같았다. 초기 일치는 성능 통과가 아니다.

검증: 전체132개 중66통과·66환경의존 생략, sim 영향 검사30개 모두 통과. 기본46관측·물리 보존, loaded 교환·반사 involution, 새 입력의 학습 gradient, Adam 확장과 optimizer.step, 48차원 저장·평가 복원을 확인했다. 첫 영향 검사는 진단용 fake 환경에 새 속성이 없어 실패했다. optional 속성이 없으면 기존 False로 처리하도록 수정했고 실패 로그를 보존했다. 기존 테스트는 수정하지 않았다.

대조 contact_obs_train_control_20261009와 후보 contact_obs_train_contact_20261009를 같은 source에서 각500k 요청으로 학습 시작했다. 대조는 source의24개 텐서와 정확히 같고, 후보는 같은 형태의17개 텐서와 기존 입력 가중치 열을 정확히 보존했다. 새 두 가중치 열은0이다. 실제 종료·회전·직진·열·기립·정지 최종 평가는 대기 중이다. 실물에서는 접촉·클러치 상태 추정이 별도로 필요하다. 기준 정책을 교체하지 않았다.
