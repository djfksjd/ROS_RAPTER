Gait-synchronised tail (user-supplied design note), digitigrade, 2026-09-28. Active DOF 10 (existing tail yaw/pitch).
Design note rules applied: tail yaw theta = A*sin(2*pi*(phi - phi0)) + K_fb*yaw_rate (+ = tail left), phi = 0 at left
  touchdown from contact, phi0 start ~ duty - 0.25; tail pitch held stiff at 0. Not applied: per-segment delays (only one
  active yaw joint; more would raise the active DOF count), 2-toe support (foot geometry change; the sickle claw is
  already a raised visual part with no collision), separate forward_command_controller (would split the 10-joint JTC
  used by the mission gate and probes). The cited papers were not verified here; all parameters were set by experiment.
Code: rock_law.GaitPhase (left-contact phase, EMA period/duty), tail_sync_targets, TailSync (yaw-rate low-pass tau,
  tail command slew limit); rock_probe.run(tail_sync=(A, phi0, K, [tau, rate]), tail_mass_scale); rock_gz_probe.py
  --tail-sync; gait_phase_node.py (read-only /gait/phase). New metrics: yaw_rate_rms, detrended yaw std, actuator work.
MuJoCo (JTCLikeServo, ankle fb, sweeps in 71-mujoco-tail-sync-sweeps.jsonl):
  no tail (tail mass x1e-3) vs fixed, kv30 base 20 s: yaw rms 0.064 vs 0.049 rad/s, x 1.14 vs 2.00 m -> the tail mass
    already helps; fast gait without tail falls at 4.8 s.
  A 0.1-0.2 rad: every phi0 raised body yaw 3-12x and most runs fell (tail momentum ~0.5 N m s >> leg yaw momentum).
  A 0.015 rad (~1 deg): fast gait (stride 0.08, 2.5 Hz, duty ~0.58) best at phi0 0.25-0.375 = duty - 0.25 (as the note
    suggests): yaw rms -19 %, detrended yaw std -33..39 %, x +3 %, leg work unchanged. Base gait (2 Hz): phi0 0.25-0.625
    tripled yaw; phase parameters depend on the gait.
  K_fb = -0.1 alone: yaw -7..16 %; +0.1/+-0.3 worse.
  Combined (A 0.015, phi0 0.3, K -0.1), 60 s fast gait: kv20 fixed falls 7.9 s -> synced no fall 7.44 m (yaw -46 %,
    slip/step 0.33); kv30 9.35 -> 9.53 m (yaw -19 %, slip 0.18); kv100 7.71 -> 7.74 m (yaw -15 %, slip 0.27).
    First fast-gait configuration without a fall across kv 20-100 in MuJoCo. Base gait kv30 got worse (5.85 -> 3.59 m).
  Filter/slew (needed for Gazebo, below): tau 0.02 s passes kv 20/30/100 for 60 s with slew 1.0 or 1.8 rad/s;
    tau 0 / 0.05 with slew 1.0 fall at kv20 (sensitive). Default TailSync(tau 0.02, slew 1.0 rad/s = 50 % of the limit).
Gazebo (fast gait stride 0.08, 2.5 Hz, 40 cycles, 71-gazebo-tail-sync-summary.json):
  fixed tail: tilt STOP at 6.70 s and 5.53 s (yaw rms 0.17, 0.16).
  synced, unfiltered K_fb: command-rate STOP at 2.81 s / 3.27 s - IMU (50 Hz) yaw rate jumps up to 0.3 rad/s per 20 ms
    at touchdowns; the watchdog blocked a 2.0 rad/s tail command as designed.
  synced, tau 0.02 + slew 1.0: tilt STOP at 6.48 s and 6.69 s (yaw rms 0.12, 0.13: about -25 %), tail command <= 0.037 rad.
  The Gazebo phase estimate is wrong: period 1.05 / 0.53 s for a 0.4 s gait (contact-message flicker); gait_phase_node
  during 2 Hz rocking reported period 0.90 s and an unknown phase. Falls are by roll, which the tail does not correct.
Conclusion: the synced tail lowers body yaw in both engines and, in MuJoCo, keeps the fast gait up across kv 20-100, but
  Gazebo still falls by roll at ~6.5 s and its contact-based phase is unreliable. Not a walking success.
