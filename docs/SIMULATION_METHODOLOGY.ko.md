# 시뮬레이션 방법론 점검 — 2026-09-28

사용자 요청: A(Gazebo servo 식별) 진행과 함께 "어떤 방식이 가장 이상적인지" 방향성 점검.
초안 검토는 UNI_AI `gpt-6-sol`(3,000 tokens)에 맡겼고, 아래 **실측**으로 수정·확정했다.
구분: **[실측]** 이번에 실행해 확인, **[관례]** 널리 쓰이는 방법, **[판단]** 이 프로젝트에 대한 의견.

## 1. 오늘 실측으로 바뀐 전제

### Gazebo 기본 DART에 servo 포화 결함 (evidence/61-*)

고정 베이스, 한 관절 near-step 명령(JTC 10ms), 100Hz 기록.

| 조건 | 결과 |
|---|---|
| 발목 0→0.05/0.08 (속도 명령 < 한도) | 정상 1차 응답, t63 ≈ 0.04s, 초과 없음 |
| 발목 0→0.15, -0.15→0 (속도 명령이 2.5rad/s 한도에 걸림) | 목표를 지나 +0.70 한도까지 +2.5rad/s로 계속 이동 후 복귀. 좌·우 발목 재현 |
| 같은 조건, 수동 발가락 없음 | 0→0.10부터 +0.70에 **고정**되어 이후 명령(0, -0.15, 0)을 따르지 않음 |
| hip pitch·knee 0→0.15 (포화) | 정상 |
| DART, step 0.5ms | 같은 결함 |
| Bullet-Featherstone, 같은 모델·명령 | 정상 |

**[실측]** 명령 경로(controller_state)는 반전됐으므로 원인은 물리 플러그인 쪽이다. 가벼운 관절이
속도 한도로 포화될 때 DART 경로에서 발생한다. upstream 이슈 번호는 확인하지 못했다.
**[가설]** 54번의 발목 ±2.5rad/s와 명령으로 설명되지 않는 속도 표본은 이 결함의 영향일 수 있다.
재실험 전에는 확정하지 않는다.

Bullet-Featherstone은 자유 기립에서 모델이 뒤집히고 12초에 27m 미끄러졌으며 수동 발가락 상태가
나오지 않았다(evidence/62). 전신 기준 엔진으로 쓸 수 없다.

### MuJoCo kv는 고정 베이스 시험으로 정해지지 않는다

**[실측]** 무부하 관절은 관성이 작아 kv 10~100 차이가 작다(발목 0.05 계단 RMSE 0.013/0.005/0.003rad).
kv 300은 발목에서 불안정했다. 기존 60번의 깨끗한 걸음은 kv 30에서만 나왔으므로
"Gazebo에 맞춘 kv"로는 답이 나오지 않고, 하중 조건의 actuator 모델 자체가 문제다.

### MuJoCo 마찰 cone (evidence/59)

**[실측]** pyramidal은 정지 기립에서 μ에 따라 미끄러짐을 만들었다. elliptic으로 고정했다.

## 2. 권장 방법 (이 프로젝트 기준)

1. **정답(ground truth)은 어떤 시뮬레이터도 아니다.** [관례: Tan 2018, Hwangbo 2019, Open Duck/BAM]
   actuator의 기준은 선택할 모터·감속기·드라이버의 사양과 향후 실측이다. 부품 미선정 상태에서는
   후보 사양 범위(토크-속도 곡선, 연속/피크 토크, 지연, 마찰, 백래시, 내부 PD)를 모델링하고
   **범위 전체를 통과**하는지로 판단한다. 한 kv에 맞춘 성공은 성과로 보고하지 않는다.
2. **역할 분리.** [판단]
   - MuJoCo: 동역학·제어기·RL 개발. actuator는 토크 한도가 있는 PD(위치) + 속도-토크 곡선 +
     지연을 무작위화한 모델로 바꾼다. 현재 Gazebo 경로 모사(velocity servo kv)는 비교용으로 남긴다.
   - Gazebo(DART): ROS 2 통합·mission gate·STOP·센서 경로 검증. 동역학 판정 기준으로 쓰지 않는다.
     관절 속도 포화가 생기지 않는 명령만 보내고, 포화+목표 초과를 감지하면 STOP하는 감시를 둔다.
3. **단계 게이트.** [관례] 관절 → 접촉 → 지지·균형 → 보행 → 지형 → mission 순으로,
   앞 단계 통과 전 다음 단계 수치를 성과로 쓰지 않는다. 정적 평발 한 발 지지는 기하상 제외.
4. **sim-to-sim 최소 검사.** [판단, 초기 기준] 같은 명령 로그를 두 엔진에 재생해 비교한다.
   관절 응답(상승시간·최대속도·정상오차 ~10%), 한도 위반 0, 접촉 판정 일치, 2Hz 흔들기 지지 순서와
   전환 시각(~20ms), 여러 조건의 넘어짐률 분포, STOP 지연. 한쪽에서만 성공하면 불합격.
5. **제어기 발전.** [판단] 개루프 수동 조정은 현상 발견까지만. 다음은 상태 피드백과
   궤적 최적화(PlaCo는 비교 기준, 평발 지지 가정은 그대로 쓰지 않음) → actuator 범위 무작위화 RL.
6. **계산 자원.** [판단] M5 CPU에서 MuJoCo/MJX 소규모 파일럿으로 초당 스텝을 먼저 측정한다.
   한 학습 반복이 하루를 넘고 앞 게이트를 통과했을 때만 유료 GPU를 검토하며, 비용·용량을 먼저 보고한다.

## 3. 이 프로젝트의 함정

1. kv 30 성공을 보행 능력으로 착각. 2. 불가능한 정적 평발 지지를 목표로 둠.
3. 발가락·마찰 차이를 제어기로 덮음. 4. ankle roll 부재를 일반 이족 가정으로 무시.
5. LLM을 안전 제어 경로에 넣음(허용 행동 선택만, STOP은 독립 ROS 게이트).
6. **[실측 추가]** Gazebo DART의 포화 결함을 로봇 결함으로 오인.

## 3.5 진행 기록 — Gazebo 흔들기 재현 (evidence/68)

- `rock_gz_probe.py`: sim time 기준 개루프 흔들기 + 포화 감시(속도 90%, 추종 오차 0.15rad, 기울기 0.25rad → STOP).
  A 0.08 / 2Hz 120주기에서 STOP 없이 교대 한 발 지지(좌·우 0.28). 포화 명령(1.88rad/s)에서 STOP 동작 확인.
- sim-to-sim: JTC horizon 50ms는 hip roll 추종을 57%로 떨어뜨렸다. 20ms에서 몸통 roll 진폭은 MuJoCo와 같지만(1.04)
  위상이 약 46ms 늦다(기준 ~20ms 미달). 한 발 지지 비율은 판정 방식(접촉 메시지 vs 힘 5%)이 달라 아직 비교 불가.
- MuJoCo `JTCLikeServo`(`rock_probe.run(jtc=(0.02, 0.02))`)로 스트리밍 JTC 경로를 모사하면 위상 차이가
  46ms → 약 21ms로 줄었다. 남은 차이는 하중 상태 servo 응답과 IMU 50Hz 표본화로 추정하며 기준 통과로 보지 않는다.
  JTC 지연을 넣어도 MuJoCo 보폭 결과는 거의 같다(kv30 0.20, kv100 0.37).
- 다음: Gazebo 보폭 시험(자세 피드백은 IMU pitch, 위치 목표만), Gazebo 접촉 힘 기준 지표.
